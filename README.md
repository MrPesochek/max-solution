# Ремонт техники в MAX

проект команды CU-company на хакатон MAX

короче идея: у магазина сломался холодильник, менеджер открывает мини-апп в максе, создает заявку и выбирает сервис. дальше все там же - сервис предлагает время выезда и смету, заказчик соглашается, мастер приезжает и в конце кидает фотки. если у сервиса своя 1С то заявки сами падают туда заказ-нарядами и статусы потом возвращаются обратно

## посмотреть

бот `t528_hakaton_max_bot`, приложение лучше открывать из него иначе не залогинит

- приложение https://hakathon.baseclub.lol
- демо 1С (это наш эмулятор) https://1c.baseclub.lol

регаться не надо, на экране выбора организации есть кнопки «Демо: я заказчик», «Демо: я исполнитель» и «Демо: оператор». там уже накиданы заявки в разных статусах, техника, переписка. демо общее на всех так что если кто то тыкает параллельно вы это увидите

что глянуть:

1. зайти заказчиком, открыть пару заявок - согласование выезда, смета, поиск исполнителя, отчет с фотками
2. зайти исполнителем - входящие, назначение мастера, цены, чат с заказчиком
3. создать заявку на технику с подключенным сервисом, она появится в CRM как заказ-наряд
4. поменять в CRM статус заказ-наряда, коннектор через какое то время подтянет его в заявку
5. оператором одобрить или отклонить новую организацию

ну и роли есть: у заказчика руководитель видит все точки а сотрудник только свои, у сервиса админ настраивает профиль и интеграцию, диспетчер работает с заявками. оператор проверяет организации и разбирает жалобы

```bash
curl -H 'Authorization: Bearer max_7d8hdiwh' \
```

сваггер https://hakathon.baseclub.lol/api/v1/docs

```bash
uv run scripts/data-api-check.py --base-url http://localhost:8080
```

## запуск локально

нужен только докер

```bash
cp .env.example .env
# заполняете .env (если надо)
docker compose up --build
```

поднимется все сразу - база, апи, воркер, фронт, эмулятор 1С и коннектор, демо данные зальются сами

- приложение http://localhost:8080 (вход через демо кнопки)
- CRM http://localhost:8082, пароль `demo`
- OData http://localhost:8082/unf_demo/odata/standard.odata/ логин `odata` пароль `odata-demo`
- статус коннектора http://localhost:8083/status

остановить `docker compose down`, с `-v` снесет еще и базу с фотками

у демо заявок есть сроки согласования и со временем они протухают, освежить:

```bash
docker compose run --rm seed python -m app.demo.seed --refresh
```

## стек

бэк python 3.13 + fastapi + postgres, фронт react + typescript + `@maxhub/max-ui`. бот, мини-апп и CRM ходят в одну логику просто через разные апи:

- `/app-api/v1` мини-апп
- `/operator-api/v1` оператор
- `/api/v1` для CRM, по ключу интеграции

воркер отдельно шлет уведомления в бота и вебхуки, обрабатывает фотки и следит за сроками заявок

коннектор к 1С в `integration_1c/`. принимает вебхуки, пишет заказ-наряды через OData, а изменения из 1С забирает опросом. настоящей 1С у нас на стенде нет поэтому сделали эмулятор с вебмордой. с живой базой тоже должно работать но поля надо будет сопоставить под конкретную конфигурацию, подробнее в [integration_1c/README.md](integration_1c/README.md)

## разработка

для тестов бэка нужен постгрес на 54329

```bash
docker run -d --name repair-test-db -p 127.0.0.1:54329:5432 \
  -e POSTGRES_USER=repair -e POSTGRES_PASSWORD=repair postgres:18.6-trixie
```

проверки

```bash
(cd backend && uv sync --frozen && uv run ruff check . && uv run mypy app && uv run pytest -q)
(cd webapp && pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test --run)
(cd integration_1c && uv sync --frozen && uv run ruff check . && uv run mypy connector emulator && uv run pytest -q)
```

если меняли апи то перегенерить схемы и типы для фронта

```bash
(cd backend && uv run python ../scripts/export_openapi.py)
cp openapi/app-api.json openapi/operator-api.json webapp/openapi/
(cd webapp && pnpm gen:api)
```

## деплой

на сервере копируем `.env.prod.example` в `.env`, заполняем домен, токен бота, секреты, пароль базы и

```bash
bash scripts/deploy.sh
```

скрипт делает бэкап, собирает образы, катит миграции и ждет пока все поднимется. если что то упало откатит образы, но миграции назад не откатываются, на такой случай есть `scripts/restore.sh`
