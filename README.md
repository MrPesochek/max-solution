# Сервис ремонта оборудования в MAX

Заказчик создаёт заявку на ремонт, выбирает сервис и согласует стоимость. Исполнитель назначает мастера, ведёт переписку и отправляет отчёт о работе. Всё это доступно в мини-приложении MAX. Сервисная компания может работать с теми же заявками из своей CRM через API.

Команда: **CU-company**.

## Попробовать

- Бот в MAX: `t528_hakaton_max_bot`.
- Мини-приложение: https://hakathon.baseclub.lol. Для входа откройте его из бота.
- Демонстрационная CRM: https://1c.baseclub.lol. (для целей демонстрации)

После входа откройте выбор организации. Кнопки «Демо: я заказчик» и «Демо: я исполнитель» дают доступ к общим примерам техники, заявок и переписки. Через «Демо: оператор» можно проверить реквизиты и представителей демонстрационных организаций, принять решение и посмотреть историю. Изменения видны другим участникам демонстрации.

В CRM на стенде работает эмулятор интерфейса и OData 1С. Коннектор обменивается с ним заявками по HTTP. Подключение к реальной базе 1С требует настройки сопоставления полей и проверки на конфигурации заказчика.

## Что можно проверить

1. Откройте демо-заказчика и выберите заявку. В примерах есть согласование выезда, смета ремонта, поиск исполнителя и отчёт с фотографиями.
2. Переключитесь на демо-исполнителя. Проверьте входящие заявки, назначение мастера, предложения стоимости и переписку с заказчиком.
3. Создайте заявку на технику с подключённым сервисом. Она попадёт исполнителю, а через коннектор появится в CRM как заказ-наряд.
4. Измените состояние заказ-наряда в CRM. После опроса коннектором изменение появится в заявке.
5. Откройте «Демо: оператор» и рассмотрите заявку на подключение организации. Для подтверждения нужны основание решения и источник проверки.

У заказчика руководитель управляет всеми точками, а сотрудник работает только с назначенными ему точками. У исполнителя администратор редактирует профиль, территорию работы, виды техники и настройки интеграции; диспетчер работает с заявками. Оператор платформы проверяет организации и разбирает жалобы. Публичная демо-проверка ограничена демонстрационными организациями.

## Локальный запуск

Нужны Docker и Docker Compose:

```bash
docker compose --env-file .env.example up --build
```

Команда поднимает базу данных, API, worker, мини-приложение, эмулятор CRM и коннектор. Миграции и демо-данные загружаются автоматически. Настоящий бот по умолчанию выключен.

| Сервис | Адрес | Доступ |
|---|---|---|
| Мини-приложение | http://localhost:8080 | Демо-вход на стартовом экране |
| CRM | http://localhost:8082 | Пароль `demo` |
| OData CRM | http://localhost:8082/unf_demo/odata/standard.odata/ | `odata` / `odata-demo` |
| Состояние коннектора | http://localhost:8083/status | Локальный адрес |

Эти пароли относятся только к локальному запуску. Порты из `.env.example` привязаны к `127.0.0.1`.

Остановить контейнеры, сохранив данные:

```bash
docker compose --env-file .env.example down
```

Запустить снова:

```bash
docker compose --env-file .env.example up -d
```

Обновить примеры заявок после истечения сроков согласования:

```bash
docker compose --env-file .env.example run --rm seed python -m app.demo.seed --refresh
```

`--refresh` пересоздаёт демонстрационные заявки. Организации и их привязки сохраняются. Команда `down -v` удаляет все тома проекта, включая базу и вложения.

## Устройство проекта

Бэкенд написан на Python 3.13 и FastAPI, интерфейс на React и TypeScript. Данные хранятся в PostgreSQL, вложения в отдельном томе. Worker доставляет уведомления и вебхуки, обрабатывает фотографии и проверяет сроки заявок.

Бот, мини-приложение и CRM используют общую бизнес-логику. Для них выделены три API:

| API | Путь | Авторизация |
|---|---|---|
| Мини-приложение | `/app-api/v1` | Сессия пользователя MAX |
| Оператор | `/operator-api/v1` | Сессия и платформенная роль оператора |
| CRM | `/api/v1` | Ключ интеграции с разрешёнными действиями |

| Каталог | Содержимое |
|---|---|
| `backend/` | API, бот, бизнес-логика, миграции и тесты |
| `webapp/` | Мини-приложение, компоненты и тесты интерфейса |
| `integration_1c/` | Коннектор, эмулятор CRM и профили сопоставления |
| `openapi/` | Схемы API и руководство интегратора |
| `deploy/`, `scripts/` | Сборка, развёртывание, резервные копии и проверки |

## Проверка API

[DATA-API.yaml](DATA-API.yaml) содержит адрес стенда, токен жюри и последовательность проверок. Токен открывает интеграционный API демонстрационной сервисной компании. Для него доступны заявки, маркетплейс, оборудование, привязки сервисов, отзывы, события и управление вебхуками.

Быстро проверить чтение основных ресурсов:

```bash
python3 scripts/jury-api-check.py
```

Базовый адрес API: `https://hakathon.baseclub.lol/api/v1`. Интерактивная схема доступна по адресу `https://hakathon.baseclub.lol/api/v1/docs`. Пример прямого запроса:

```bash
curl -H 'Authorization: Bearer max_7d8hdiwh' \
  https://hakathon.baseclub.lol/api/v1/me
```

Полный локальный сценарий создаёт заявку, проверяет разделение организаций, идемпотентность и обмен с CRM:

```bash
uv run scripts/data-api-check.py --base-url http://localhost:8080
```

Проверить паспорт и схемы без HTTP-запросов:

```bash
uv run --no-project --with-requirements scripts/vendor/example-data-api/requirements.txt \
  python scripts/vendor/example-data-api/validate_data_api.py DATA-API.yaml
uv run scripts/data-api-check.py --validate-only
```

## Разработка и тесты

Для тестов бэкенда сначала поднимите PostgreSQL:

```bash
docker compose -f compose.dev.yaml up -d
```

Из корня репозитория:

```bash
(cd backend && uv sync --frozen && uv run ruff check . && uv run mypy app && uv run pytest -q)
(cd webapp && pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test --run && pnpm build)
(cd integration_1c && uv sync --frozen && uv run ruff check . && uv run mypy connector emulator && uv run pytest -q)
```

Тесты бэкенда создают отдельную временную базу на порту `54329`. Тесты интерфейса используют MSW, тесты коннектора используют локальные заглушки HTTP.

После изменения API обновите схемы и типы:

```bash
(cd backend && uv run python ../scripts/export_openapi.py)
cp openapi/app-api.json openapi/operator-api.json webapp/openapi/
(cd webapp && pnpm gen:api)
```

## Развёртывание

Для сервера используйте `.env.prod.example` как основу `.env`. Укажите домен, токен и имя бота, секрет вебхука, пароль PostgreSQL и ключ шифрования. Параметр `DEMO_SHOWCASE_ENABLED=true` открывает демонстрационные организации после обычного входа через MAX. Он не включает вход по произвольному демо-пользователю.

```bash
bash scripts/deploy.sh
```

Скрипт создаёт резервную копию, собирает образы, применяет миграции и проверяет состояние сервисов. При неудачном обновлении он пытается вернуть предыдущие образы. Откат образов не отменяет миграции базы.

Настройка домена, бота, резервных копий и восстановления описана в [docs/deploy.md](docs/deploy.md). Подключение 1С описано в [integration_1c/README.md](integration_1c/README.md), контракт CRM в [openapi/README.md](openapi/README.md).
