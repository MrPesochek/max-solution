# Коннектор 1С и демонстрационная CRM

Коннектор получает заявки платформы через вебхуки и создаёт заказ-наряды через OData. Изменения заказ-нарядов он передаёт обратно через `/api/v1`. На демонстрационном стенде вместо базы 1С работает эмулятор с веб-интерфейсом и совместимым подмножеством OData.

## Запуск

Из корня репозитория:

```bash
docker compose --env-file .env.example up --build
```

CRM откроется на http://localhost:8082 с паролем `demo`. OData доступен по адресу `http://localhost:8082/unf_demo/odata/standard.odata/`, логин `odata`, пароль `odata-demo`. Эти настройки предназначены для локального стенда.

Для разработки из каталога `integration_1c`:

```bash
cp .env.example .env
uv sync --frozen
```

Укажите ключ сервисной компании в `CONNECTOR_PLATFORM_API_KEY`. Затем в двух терминалах запустите:

```bash
uv run uvicorn emulator.main:app --port 8082
uv run uvicorn connector.main:app --port 8083
```

## Обмен заявками

Входящий вебхук проверяется по HMAC и сохраняется в SQLite. Повторное событие с тем же `event_id` не создаёт второй заказ-наряд. Номер документа записывается в заявку платформы, а фотографии прикрепляются к документу CRM.

Коннектор опрашивает `DataVersion` документов. При изменении состояния, времени выезда или стоимости он отправляет соответствующее действие на платформу. После сбоя обмен восстанавливается по ленте `/events`. При конфликте версии коннектор перечитывает заявку перед повтором действия.

Сопоставление полей, состояний и действий хранится в `profiles/unf.yaml`. Для другой конфигурации используйте копию этого профиля или `profiles/generic.yaml`.

## Подключение базы 1С

1. Опубликуйте базу с OData по HTTPS.
2. Включите в OData заказ-наряды, контрагентов, состояния, номенклатуру, дополнительные реквизиты и присоединённые файлы из профиля.
3. Создайте отдельного пользователя OData с правами на нужные объекты.
4. Настройте дополнительные реквизиты и состояния заказ-наряда по профилю.
5. Сверьте имена объектов с `$metadata` базы и проверьте обмен на тестовом заказ-наряде.

Имена объектов зависят от конфигурации и её версии. Готовый профиль нужно проверить на базе заказчика перед подключением. Подробности и ограничения перечислены в [описании интеграции](../docs/architecture/06-1c-integration.md).

## Настройки

Все переменные коннектора имеют префикс `CONNECTOR_`.

| Переменная | Назначение |
|---|---|
| `PLATFORM_API_BASE_URL`, `PLATFORM_API_KEY` | Адрес API платформы и ключ сервиса |
| `PUBLIC_BASE_URL` | Адрес коннектора для приёма вебхуков |
| `ONEC_ODATA_URL` | Адрес OData базы |
| `ONEC_USERNAME`, `ONEC_PASSWORD` | Учётная запись OData |
| `ONEC_VERIFY_TLS` | Проверка сертификата или путь к доверенному CA |
| `ONEC_ALLOW_HTTP` | HTTP для локального эмулятора |
| `PROFILE` | `unf`, `generic` или путь к своему YAML |
| `POLL_INTERVAL_SECONDS`, `POLL_BATCH_SIZE` | Интервал опроса и размер пачки |
| `DATABASE_PATH` | SQLite с состоянием обмена |

Настройки эмулятора имеют префикс `ONEC_EMULATOR_`. Для публикации задайте свои `ODATA_PASSWORD`, `UI_PASSWORD`, `SESSION_SECRET` и выключите `ALLOW_DEFAULTS`. Полный список переменных находится в [.env.example](.env.example).

```bash
uv run mypy connector emulator
```
